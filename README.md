# 열어조 CO₂ 시계열 예측 모델

최근 **5분 동안 10초 간격으로 측정한 31개 기록**을 입력받아 미래 CO₂를 예측합니다. 닫힘 모델은 계속 닫아 둔 경우, 열림 모델은 계속 열어 둔 경우를 예측합니다. 실제로 학습한 회귀·신경망 가중치를 사용합니다. LSTM/GRU 구현은 아니며, 과거 측정값의 지연값·변화량·변동성·과거 창문 상태를 특징으로 사용하는 시계열 회귀입니다.

**현재 포함된 모델은 합성 데이터로 학습한 실험용 모델입니다. 실측 환경의 정확도, Raspberry Pi 처리 시간, 실제 모터 동작은 아직 검증하지 않았습니다.** 실제 센서 데이터 CSV로 재학습하는 코드까지 포함했습니다. AWS 배포, 외부 API 호출, MQTT 연결, 물리 모터 구동은 실행하지 않았습니다.

이 컴퓨터에서는 PowerShell에서 다음을 실행합니다. 기존 Codex 번들 Python과 NumPy를 사용하므로 추가 설치가 필요하지 않습니다.

```powershell
cd 'C:\Users\임나경\Documents\ChatGPT\AIoT\ai'
.\start.ps1
```

브라우저에서 <http://127.0.0.1:8765>를 열면 실제 모델 추론 결과와 개폐 판단을 확인할 수 있습니다. 8765 포트가 이미 사용 중이면 `.\start.ps1 -Port 8766`으로 실행합니다. 종료는 실행 창에서 Ctrl+C입니다. PowerShell 실행 정책을 변경할 필요 없이 Python 명령으로 직접 실행할 수도 있습니다.

일반 Python 환경에서는 Python 3.11 이상과 NumPy가 필요합니다.

```powershell

python -m ventilation_ai serve
```

`start.ps1 -Python '원하는 Python 실행파일의 절대경로'`로 실행 환경을 지정할 수도 있습니다.

## 모델이 입력받는 내용

`examples/history.json`에 입력 형태, `examples/telemetry_template.csv`에 CSV 열 예시가 있습니다. 두 파일 모두 합성 예시이며 실측 파일이 아닙니다.

| 필드 | 의미 |
|---|---|
| timestamp | UTC epoch 초 또는 시간대가 포함된 ISO 시각 |
| run_id | 독립된 실험 회차 식별자 |
| co2_ppm | 현재 실내 CO₂ |
| temp_c, humidity_pct | 실내 온도·상대습도 |
| outdoor_co2_ppm | 외기 CO₂. 미측정 시 가정값임을 실험 기록에 명시 |
| outdoor_temp_c, outdoor_pm25_ugm3 | 외기 온도·PM2.5 |
| window_open | true/false. 이 시각부터 다음 표본까지 적용되는 실제 창문 상태 |
| window_changed_at | 실제 창문 상태가 마지막으로 바뀐 시각 |
| outdoor_observed_at | 외부 정보 관측 시각 |
| source | MEASURED / SYNTHETIC / SCENARIO |
| outdoor_source | 외부 값의 출처: MEASURED / SYNTHETIC / SCENARIO |

입력은 시간순이어야 합니다. 중복·역순·회차 혼합·NaN·범위 오류를 거부합니다. 10초 간격이 끊긴 구간을 임의로 보간하지 않습니다. 31개가 쌓이기 전에는 모델이 `UNAVAILABLE`을 반환하며, 현재값이 유효한 경우 규칙으로 판단합니다. 모델 추론에서는 최신값이 30초 넘게 오래되었거나 미래 시각이면 사용하지 않습니다. 외부 PM2.5는 CO₂ 학습 특징이 아니라 제어 규칙에 사용합니다.

모델은 물리적으로 동일한 상자와 동일한 개방 방식에 적용하는 것이 전제입니다. 상자 부피·플랩 면적·팬 설정을 바꾸면 재수집·재학습해야 합니다. 실시간 제공할 수 없는 발효병 설정이나 미래 측정값은 입력 특징으로 사용하지 않습니다.

## 예측과 개폐 판단

- 닫힘 예측: 1·2·3·5·10·15분 뒤 CO₂. 15분 예측과 두 번의 연속 확인으로 필요 여부를 판단합니다.
- 열림 예측: 10·30·60·90·120·180·300·450·600초 뒤 CO₂. 곡선에서 800ppm을 처음 통과하는 시간을 보간합니다.
- 이미 열려 있다면 600초 상한까지 남은 시간 이내의 구간만 제공합니다. 예를 들어 500초째 열려 있으면 10·30·60·90초 예측만 제공합니다. 이미 목표 농도 이하이면 `ALREADY_AT_TARGET`입니다.
- 예측 곡선은 해당 미래 창문 상태와 외부 조건이 유지된다는 가정입니다. 예측을 보고 실제로 창문을 열었다면 이후 실측을 '닫힘 유지 예측'의 정답으로 평가하지 않습니다.
- 600초 이내 목표 도달이 예측되지 않으면 `target_eta_sec: null`, `NOT_REACHED_WITHIN_HORIZON`을 반환합니다. '600초면 목표 도달'이라는 정답을 만들어내지 않습니다.
- 환기 시작이 예약된 경우 지속 시간은 `null`이며 개방 직전에 다시 계산합니다. 현재 800ppm 이하라는 이유로 미래 예약의 지속 시간을 0초로 정하지 않습니다.
- 표시되는 오차 범위는 검증 회차의 절대 오차 90백분위입니다. 보장된 90% 신뢰구간이 아닙니다. 학습 특징 범위를 크게 벗어나면 해당 예측은 제어에 사용하지 않습니다.

`Controller`는 실제 장치가 보고한 개폐 시각을 기준으로 시간 제한을 적용하며, 반환값은 **명령 추천**입니다. 모터 명령 전송과 응답 확인은 별도의 장치 어댑터가 맡아야 합니다.

## 판단 규칙과 명시한 해석

현재 CO₂ 1,000ppm 이상은 즉시 판단합니다. 예측만 기준을 넘으면 서로 다른 연속 1분 구간에서 두 번 확인하고, 예상 도달 60초 전에 시작합니다. 매 10초 요청이나 같은 시각 재요청은 연속 확인 횟수를 늘리지 않습니다.

PM2.5는 `≤35`, `>35~≤75`, `>75`로 구분합니다. 이는 소수 센서값도 빈틈없이 처리하기 위한 경계 해석입니다. 나쁨은 최대 120초, 매우 나쁨은 원칙적으로 보류하되 현재 CO₂ 2,000ppm 이상이면 최대 60초입니다. 기온 ≤0°C 또는 ≥33°C이면 일반 환기 시간을 절반으로 줄이며 최종 최소 10초를 유지합니다.

보호 모드는 4,500ppm에서 진입하여 3,000ppm 이하에서 해제합니다. 외부 PM·기온 제한을 무시하지만, 앞서 제안한 해석대로 **최대 열림 600초와 닫힌 뒤 300초 재개방 간격은 보호 모드에도 적용**합니다. 보호 해제는 정상 규칙으로 돌아간다는 뜻입니다. 600초에 도달하면 반드시 닫기 요청을 내며, 새 예측이 도착해도 기존 개방 예산을 계속 연장하지 않습니다.

예측을 사용할 수 없으면 현재값 규칙과 물질수지식으로 전환합니다. 대체 계산의 기본 ACH=20회/h, 발생량=0ppm/s는 설정 가정입니다. 발효병 발생이 지속되면 이 가정이 맞지 않을 수 있으므로 `Policy`의 `fallback_ach`, `fallback_source_ppm_sec`를 실험값으로 보정해야 합니다. 발생량 때문에 목표가 평형 농도보다 낮으면 대체 계산도 도달 불가를 반환합니다.

## 학습과 재학습

```powershell
# 재현 가능한 합성 실험 48회, 총 34,560개 측정값
python -m ventilation_ai simulate --runs 48 --output data/synthetic.csv

# 회귀와 작은 신경망을 실제로 학습·비교
python -m ventilation_ai train --data data/synthetic.csv --output artifacts/demo_model

# 실측 데이터가 준비되면 별도 모델 폴더에 학습
python -m ventilation_ai train --data data/measured.csv --output artifacts/measured_model

# 파일의 마지막 구간을 과거 시각 기준으로 재생하여 예측
python -m ventilation_ai predict --data data/measured.csv --model artifacts/measured_model

# 세 제어 방식의 동일 조건 시뮬레이션 비교
python -m ventilation_ai benchmark --model artifacts/demo_model

python -m unittest discover -s tests -v
```

한 실험 회차의 표본을 학습/평가에 무작위로 섞지 않습니다. 회차 시작 시각순으로 앞 60% 학습, 다음 20% 검증, 마지막 20% 테스트에 배정합니다. 정규화 값은 학습 자료에서만 추정하고, 모델·규제 강도·조기 종료는 검증 자료로 선택합니다. 테스트 자료는 모델 선택에 사용하지 않습니다.

각 미래 구간은 그 구간 전체에서 창문 상태가 유지된 경우에만 정답으로 사용합니다. 중간에 개폐가 바뀐 구간과 데이터 공백은 마스킹하여 학습에서 제외합니다. 600초 개방 정답은 충분히 길게 관측한 개방 회차에서만 얻습니다. 센서 기록 수가 많아도 독립 실험 수가 부족하면 일반화 검증을 대신할 수 없습니다. 코드의 최소 9회는 입력 검증 하한이며 성능 확보에 충분한 실험 횟수를 의미하지 않습니다.

기준선은 현재값 유지와 최근 1분의 선형 추세입니다. 학습 후보는 규제 선형회귀(Ridge) 3종과 은닉층 48개 노드의 작은 MLP입니다. 닫힘·열림 모델을 각각 검증하여 선택합니다. 재학습 때 더 복잡한 모델이 항상 선택되지는 않습니다.

SHA-256은 파일 손상 검출용이며 모델 발행자 인증을 대신하지 않습니다. 클라우드 배포에서는 인증된 전송·서명 검증·버전 롤백을 별도로 적용해야 합니다. 현재 모델은 NumPy 형식이며 TFLite 변환은 포함하지 않았습니다. Python+NumPy 환경에서 추론 가능하고, Raspberry Pi에서 실제 속도 측정은 남아 있습니다.

## 로컬 API와 연결 범위

서버는 127.0.0.1에만 바인딩합니다. 인증·TLS가 없는 개발용 API이므로 인터넷에 공개하는 운영 서버로 사용하지 않습니다.

- `GET /api/model`: 모델 버전·학습 출처·평가 결과.
- `GET /api/demo?scenario=rising`: 합성 이력을 실제 모델에 넣어 추론하는 화면용 예시. `SIMULATION` 표시.
- `POST /api/forecast`: `{"history": [측정기록, ...]}`. 실시간 기준 최신 데이터만 사용. 상태 없는 예측 전용.
- `POST /api/telemetry`: `{"device_id":"lab-01","reading":측정기록}`. 측정값 누적, 예측, 상태 있는 추천, SQLite 저장.
- `GET /api/devices/lab-01/latest`: 최신 측정·예측·추천. 오래된 응답의 개방 추천은 `UNAVAILABLE`로 바꿉니다.

telemetry의 `device_id+timestamp`는 멱등키입니다. 같은 데이터 재전송은 기존 응답을 반환하고, 같은 키의 다른 데이터는 오류입니다. 제어기 상태를 SQLite에 저장하여 서버 재시작 후 보호 모드·기존 개방 예산을 복원합니다. 합성/혼합 데이터로 학습한 모델은 라이브 telemetry 경로에서 자동으로 제어에 사용하지 않고 현재값 규칙으로 전환합니다. 합성 모델 사용은 명시적인 데모·벤치마크 경로에 한정합니다.

기존 `ui/` 대시보드는 데모 구현을 보존했습니다. 여기의 API는 AI 개발용 별도 규격이며 기존 화면의 AWS API 제안 규격과 자동 호환된다고 가정하지 않습니다. 장치 어댑터에서는 이 모듈의 `Predictor`·`Controller`를 직접 호출하고, 실제 모터 ACK·위치·동작 타임아웃을 연결해야 합니다. 클라우드에는 측정/예측/추천을 전송하고, 이 모델 폴더를 버전별로 배포하는 방식으로 확장할 수 있습니다.

## 검증 범위

단위·통합 테스트로 시계열 입력 검증, 미래 행동 정보 누출 방지, 목표 도달 불가, 임계값과 시간 제어, 학습 파일 로드, 재요청 처리와 상태 저장을 확인합니다. 벤치마크는 같은 물리 조건과 센서 잡음으로 세 제어기를 비교합니다. 기준 초과 시간 감소와 총 개방 시간 증가를 함께 보고하며 에너지 절감으로 해석하지 않습니다.

브라우저에서 로컬 페이지를 여는 작업은 보안 승인 단계에서 거절되어 시각적 검증을 완료하지 못했습니다. 페이지 구문 및 화면이 호출하는 애플리케이션 로직은 별도로 검사했습니다. 실제 센서·모터, AWS, TFLite, 실측 성능 및 Raspberry Pi 추론 속도는 검증 범위에 포함되지 않습니다.
